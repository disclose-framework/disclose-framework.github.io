Disclose

Let any agent see how a merchant actually performs before it buys.

Agents can already read price, availability, reviews, and policy text. They still cannot reliably see refund speed, on-time shipment, chargeback ratios, or return rates. Disclose is an open standard for merchants to publish those performance signals at /.well-known/disclose.

No scores. No badges. The agent computes its own confidence from attested observations, weighted for the buyer it works for.

01 · Discovery

One file on the merchant's domain.

Merchants publish a structured disclosure document at /.well-known/disclose. Agents that know the convention fetch it directly. Fallbacks exist for platforms that do not support the well-known path. No central registry of merchants is required.

02 · Attestation

Source and strength are explicit.

Every signal carries an attestation level: none (self-reported), computed (pulled from a platform API), or signatory (cryptographically signed by a named third party). Agents decide how much weight each level earns.

03 · Scope

Merchant, offer, or item.

Signals can be published at merchant, offer, or item scope. An agent comparing the same product across two sellers can read entity-level performance and, when available, SKU or item-level attributes from the same endpoint.

Position

Sits below discovery and above the transaction.

UCP and ACP handle product discovery and checkout. MCP is the tool layer most agents already use. AP2 covers payment authorization. None of them standardize merchant performance signals: refund processing time, on-time shipment, chargeback rates, dispute outcomes, return rates, or platform tenure.

UCP answers how to buy. Disclose answers whether to buy, and from whom. It supplies machine-readable evidence and nothing else. No scores, badges, rankings, or recommendations. Agents weight the signals by their own risk models and the buyer's context.

Signatories

A number is a claim. A Signatory makes it an argument.

The schema and the endpoint are easy to copy. What matters is who stands behind the data. A Signatory is a named third party that already holds a merchant's operational data and cryptographically signs specific signals. If the number is wrong, the Signatory's own reputation takes the hit.

none
Self-reported by the merchant. Useful, but unverified.
computed
Calculated from platform data via API. Harder to fake.
signatory
Signed by a named third party with something to lose.

Returns platforms, logistics providers, and payment processors are natural Signatories. The strongest are BNPL providers. They carry direct financial exposure when a merchant fails to deliver, so their attestations are backed by capital, not just reputation.

Platforms attesting to their own merchants have a conflict of interest. Independent Signatories are the design choice that keeps the evaluation layer from belonging to any one platform.

Example

One endpoint. Provenance attached to every value.

An agent fetches a single disclosure document. Each signal arrives with its attestation level, observation window, and freshness metadata, so the agent knows what it is looking at and how recent it is.

Simplified and illustrative. See the spec for the full disclosure document. Agents interpret; the standard does not.

Governance

MIT licensed. Maintainer-led while the profile is validated.

Disclose is published as a framework, not a protocol. The distinction is intentional. The Core Commerce Profile, the merchant publishing model, the agent consumption model, and the Signatory registry are still being validated through implementation.

The specification is designed to be owned by no single company. Independent governance is the goal once merchants, agent platforms, infrastructure providers, and Signatories are participating. Every material change happens in public on GitHub.

Working Group

The spec is live. The first cohort is forming.

The schema and reference tooling exist, including an MCP server agents can call to fetch disclosures. The next step is testing the model against real merchant data and real agent workflows.

We are looking for merchants willing to publish, potential Signatories willing to attest signals they already compute, and agent teams willing to consume the data and tell us what is missing.
